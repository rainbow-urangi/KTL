# Business Process Abstraction contract v1 — precomparison design

Authority: latest user authorizes Business Process Abstraction Layer, preserving v1.2.1 and raw provenance, grouping same-form field editing, and representing automatic submit/API/popup/outcome as evidence when they express one intent. This supersedes the earlier one-raw-atom granularity and passive-outcome standalone RESULT_CHECK rule. GT/score/BU/event exceptions/current deployed UI are forbidden serializer inputs. FINAL p7 formulas and five-target scope remain; no target step count is configured.

## Serializer contract

Pure serializer accepts raw evidence ledger and frozen model source membership (event/node/map identifiers only), not GT, matching, predictions.json, business labels, target counts or metrics. Raw user action and generic verb taxonomy determine intents. Distinct/ambiguous map membership is preserved; no optimal map selection. An unmapped raw intent remains an unresolved generated intent in UNMAPPED_RAW, not silently dropped. No model inference is run.

Field editing is one INPUT only for a contiguous run of actual input/change/paste under identical session, full page, explicit form/context identity and source map. Form identity is an explicit form id/selector or a dynamic popup identity with captured form-container selector; different explicit inner forms remain distinct. Same page alone, field name prefix, GT object text or temporal closeness cannot establish form identity. Unknown form keeps separate field intents. Focus on an input is contextual evidence; it does not split a known same-form edit. Different user intent, popup scope or page/context resets grouping. All field labels, IDs, types, selectors, source events/nodes remain in the canonical field list; raw values are not newly exposed.

SAVE/REGISTER/UPDATE are direct user verbs. REGISTER whose explicit causal popup opens an edit form is INITIATE; post-input register in the same proven form is COMMIT; otherwise phase is UNKNOWN. Repeated independent writes are not merged. Submit/HTTP/outcome are attached only via unique exact recorded causal identity with compatible session/page/order and no pending intervening operation. API recent_action_fallback and last-user pointers are never direct proof. Explicit GET stays read evidence; write status does not prove completion.

A popup success assertion with matching explicit opener/opened_by/cause IDs to a completed write, or explicit ui_outcome source_interaction_id, can prove normal completion. Conflicting IDs, future/negated messages, stale write, unknown phase, different session/page or new intervening input/write block completion. All raw popup/HTTP/submit/outcome objects and relationship strategy remain losslessly preserved in original raw/technical ledgers, linked or unlinked. Acknowledgement/X/close is context, not a new completion intent. Genuine independent user result-check verbs remain RESULT_CHECK. User-selected nonform detail open remains DETAIL_OPEN. Route/page-load/popup lifecycle alone is context; explicit menu-entry gesture remains a business intent.

One canonical business step has stable generated_step_id, process/workflow ID, ordered intent, business context, optional business object/form identity, fields, HTTP/completion evidence, source_event_ids/source_node_ids, intent_source_event_ids, evidence, serializer_rule_id and resolution_status. Source_event_ids includes attached attributable evidence; ownership still uses only execution manifest ranges after serialization. Mixed involving target BUs is counted once/ineligible, unknown ownership retained, all split maps included. All raw event IDs must appear in the evidence disposition ledger; no technical evidence deleted.

## Deterministic evaluation contract v1

Unavailable/invalid dataset, hashes/schema or missing independent gate remain null. For a valid frozen dataset, absent semantic/causal proof yields UNMATCHED generated intents and MISSING required GT predicates, with uncertainty reasons, rather than aborting the entire measurement or assuming success. This is expressly user-authorized evaluation policy, not retrospective tuning.

Independent-intent roles (entry/select/input/initiate/commit/save/explicit user check) use typed action, direct canonical target/context, order-preserving one-to-one matching. Only exact normalized declared labels/aliases and symmetric grammatical input/selection suffixes are permitted. No English URL translation or current deployment registry. Input field lists and graph/raw sidecars are not alternate GT labels: grouped INPUT requires its directly generated form/business-object label to satisfy a whole-information requirement.

TD-04 normal-end and passive completion-display requirements are state predicates, because latest user explicitly puts automatic success in write attributes rather than standalone generated steps. A state predicate is supported only by canonical explicit completion evidence on an already one-to-one matched completed write in the same execution/context, before the GT predicate and with no later pending operation. If the source GT explicitly requires RESULT_CHECK action, it remains an independent user intent. No generated step is duplicated. State evidence cannot create a direct match for an otherwise unmatched write or substitute a context/action.

Accuracy numerator counts unique correctly mapped generated business intents, once each. Completeness numerator counts distinct included required GT intent/state predicates, once each. These numerators need not be equal for a composite action with completion attributes. Denominators are all generated target business steps (plus related mixed once) and all original required GT procedures. This follows the two distinct FINAL p7 definitions and the latest single-write-plus-completion representation; it does not lower either denominator. CSV distinguishes direct intent mappings and supported state predicates and includes provenance. No auxiliary item independently increases Accuracy.

Serializer/abstraction rules and evaluator contract/dependencies are hash-frozen before actual comparison. Development runs only synthetic comparator fixtures. Independent Verification must approve this compositional mapping/count policy, granularity, raw causal proof, total evidence coverage and uncertainty treatment before any real GT comparison. Model weights/threshold/features/clustering stay unchanged; M06/M03/OFFICIAL stay stopped. Below75 after valid measurement means mismatch analysis only, no further tuning.

## Conservative counterexample clarifications

A generic repeated-DOM tree parser alone is not proof of a navigation-menu control; a captured nav/sidebar menu or explicit menuitem role is required. Independent unknown button attempts remain UNRESOLVED. CANCEL or unknown pending operation prevents stale normal-end proof. Multiple observer records for one write are evidence of one completion state: the same state role is covered at most once per matched write even when popup and ui_outcome both observe it. END and passive completion-display are distinct declared state aspects; repeated copies of either are not double-counted.

HTTP evidence preserves original method/status/raw endpoint and a case-preserving normalized path (numeric/UUID segments typed generically, query retained in raw endpoint). Explicit GET can support read/query intent, never a write; explicit write response supports only write intent, never normal completion by status alone. Fallback remains unlinked.

## Independent A1/A2/A3 corrections, abstraction revision 1.1

INPUT aggregation now requires the same nonempty proven business context as well as form/session/page/map. Missing context is not a merge wildcard; an explicit different context splits. Registration COMMIT input support also requires that same proven context. All opener consumers use one raw-only validator: every supplied opener/opened_by/cause/parent/related event or interaction reference must resolve consistently to one existing source on the same session/full page, strictly before the popup. Invalid references remain in raw plus validation audit with reason, never replaced. Only a validated opener can prove registration initiation, detail opening, inherited form business context or popup success completion.

Per-event disposition/CSV separately exports original_graph_memberships and original_occurrence_memberships with all one-to-many original references and explicit source array paths. These are trace-only; canonical source_process_ids/source_node_ids and intent map selection are not reassigned from noncanonical graph evidence. References outside the raw ledger remain unresolved metadata rows, not invented raw events. No original graph or occurrence is removed. The comparison/count/missing-evidence contract remains unchanged.
