KTL 집 PC 실행 안내 (Windows / Python 3.12)

1. 저장소와 기본 환경

이 저장소의 feature/jinseok 브랜치를 집 PC의 원하는 폴더에 clone합니다.
<repository-url>에는 본인 저장소 주소를 넣습니다. 이미 clone했다면
저장소 폴더에서 git pull --ff-only origin feature/jinseok으로 갱신합니다.

  git clone --branch feature/jinseok <repository-url> KTL
  cd KTL

아래 명령은 README.md와 backend 폴더가 있는 저장소 최상위에서 실행합니다.
Python 3.12, Git, Google Chrome을 설치합니다. Node.js는 UI 회귀 시험을
직접 실행할 때만 필요하며 웹 서버 실행 의존성은 아닙니다.

  py -3.12 -m venv .venv
  .\.venv\Scripts\python.exe -m pip install -r requirements.txt
  if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }

홈 실행 requirements.txt는 검증 환경의 Selenium 4.51.0으로 고정합니다.
기존 backend/m04/requirements.txt의 호환 범위는 변경하지 않습니다.
처음 Selenium을 실행할 때 Chrome에 맞는 driver를 준비하기 위한
인터넷 연결이 필요할 수 있습니다. 웹 UI 표시 자체는 Chrome/driver/
시험 계정/OpenAI 설정이 없어도 가능합니다.

2. 개인 설정

.env.local을 로컬 편집기로 열어 필요한 항목만 채웁니다. 파일 내용을
공유하거나 Git에 추가하지 않습니다. .env.example에는 실제 값이 없습니다.

  KTL_M04_RBEM_USERNAME : RBEM 시험 계정 ID
  KTL_M04_RBEM_PASSWORD : 해당 시험 계정 비밀번호
  KTL_M07_OPENAI_API_KEY : GPT 코드 생성을 사용할 때의 개인 API 키
  KTL_M07_MODEL : 해당 키로 요청 가능한 모델 식별자

서버 시작 도구는 RBEM 로그인 2개 항목만 기존 loader로 읽습니다.
이미 프로세스 환경변수로 지정한 값이 있으면 그 값을 유지합니다.
M07은 기존 generator가 .env.local의 키와 모델 설정을 직접 읽습니다.
원래 OPENAI_API_KEY 환경변수도 지원하지만 예제에서는 전용 키 이름을
사용합니다. 빈 키/모델은 미설정 상태이며 시작만으로 GPT를 호출하지 않습니다.

3. 실행과 종료

  powershell -ExecutionPolicy Bypass -File .\scripts\start_local.ps1

또는 PowerShell 실행 정책 변경 없이 Python으로 시작합니다.

  .\.venv\Scripts\python.exe -B -X utf8 .\scripts\start_local.py

터미널에 표시한 http://127.0.0.1:8000 주소로 접속합니다.
예: http://127.0.0.1:8000/metrics/m01?mode=DEVELOPMENT
포트가 이미 사용 중이면 기존 서버를 확인하거나 다른 포트를 지정합니다.

  .\.venv\Scripts\python.exe -B -X utf8 .\scripts\start_local.py --port 8001

시작 도구는 다른 서버를 종료하거나 backend/config.json을 덮어쓰지 않습니다.
현재 Python 실행 파일의 폴더를 자식 프로세스 PATH 맨 앞에 두므로
portable 'python' adapter 명령도 같은 가상환경을 사용합니다.
프로젝트 폴더 이름에 공백이 있어도 실행할 수 있습니다.
종료할 때 서버를 시작한 터미널에서 Ctrl+C를 누릅니다.
backend 소스를 변경했다면 서버를 종료하고 다시 시작해야 합니다.

4. 기능별 준비 사항

M01 CSV:
수집기의 실제 events.csv를 DEVELOPMENT 화면에 업로드합니다. 수집기는
이 저장소 바깥의 별도 확장 프로그램이므로 새 PC에도 별도로 준비합니다.
업로드 원본과 기존 기준에 대한 개발 비교를 사용하며 공식 결과로 간주하지 않습니다.

M03 canonical/API:
페이지 조회는 모델 추론이나 업로드 CSV 분석을 실행하지 않습니다.
생성 버튼은 설정된 context를 조회하고 M03 생성 API와 결과 접수 API를
사용합니다. 정상 canonical 생성에는 분석 manifest, canonical JSON,
process_models CSV 및 해당 SHA가 실제로 일치해야 합니다.
이 브랜치에는 기본 개발 canonical 입력(manifest/JSON/CSV)을 포함합니다.
이 입력의 변환·시나리오 보관은 새 AI 모델 추론이나 정답 평가가 아닙니다.
다른 입력을 쓰려면 실제 분석 입력을 별도로 준비해 M03 연결 설정에
프로젝트 상대 경로와 출처/업무 정보를 지정합니다. 외부 실제 생성기를
사용하려면 제공받은 API와 해당 입력·인증 설정을 별도로 연결합니다.
이 서버의 내부 접수 URL을 외부 생성기로 재설정하지 않습니다.
외부 API 인증은 해당 연결의 auth_env에 지정한 프로세스 환경변수로
별도 설정합니다. 서버나 문서에 인증값을 저장하지 않습니다.
정답 업무 순서가 없으면 생성·보관과 평가를 구분하고 score는 null입니다.

M04 수집 동작 재현/고정 스크립트:
같은 서버 세션에서 M01에 CSV를 업로드하고 M04의 'M01 수집 동작'을
불러옵니다. 필요한 입력값을 직접 채워 고정 스크립트로 가져온 다음
실행 버튼을 별도로 누릅니다. 가져오기만으로 Chrome은 시작하지 않습니다.
대상 식별 정보가 부족한 행이나 지원하지 않는 동작은 차단 사유를 표시하며
값을 추정하거나 원본 CSV를 고쳐 우회하지 않습니다.
'새 창으로 실행' 기본 선택은 Chrome에 동작을 표시하고 마지막 화면을
15초 유지하는 옵션입니다. 실제 실행은 대상 업무에 입력/등록 요청을
보낼 수 있으므로 시험 계정과 실행할 동작을 먼저 확인합니다.
M03 시나리오의 GPT 코드 준비/외부 Python 등록은 기존 별도 경로로 유지됩니다.

M07 GPT:
실행 조건이 준비된 M03 시나리오와 API 키/모델을 설정한 후 명시적으로
코드를 생성합니다. 생성, 문법 검사, 실제 실행의 상태·분모를 구분합니다.
미시도/공급자 제한/평가 대기는 성공으로 계산하지 않습니다. HTTP429가
표시되면 안내된 대기 상태를 확인하며 자동으로 재요청하지 않습니다.

M02/M05/M06 및 공식 평가:
기존 모델/분석 입력/로컬 캐시와 별도 의존성이 필요한 기능은 기본
Selenium 설치만으로 준비되지 않습니다. historical V6.2 복구용
model/v6_2/inference/requirements.txt는 별도 실행 환경용입니다.
특히 M02/M06 전체 추론에 필요한 약 500MB의 원본 events 데이터와
로컬 E5 snapshot은 Git에 포함되지 않습니다. 기존 분석 manifest에
기록된 정확한 원본 위치와 SHA를 본인의 개발 PC에서 확인한 뒤 별도로
안전하게 복사·설정해야 합니다. 개인 로컬 경로와 원본 데이터 값을
이 안내에 기록하지 않으며, 개인 CSV와 비밀 설정을 공유 저장소에
push하지 않습니다. 이 자료가 없으면 전체 모델 추론까지 재현됐다고
볼 수 없습니다.
승인 산출물·가중치·평가 정답을 새로 만들거나 학습해 대체하지 않습니다.
공식 manifest/GT가 준비되지 않은 상태의 공식 판정은 null입니다.

5. 집 PC에서 새로 시작되는 상태

.env.local, 기존 업로드/비교/실행 결과, 로컬 모델 캐시, 수집기와 개인
브라우저 프로필은 Git clone으로 옮겨지지 않습니다. 새 서버 세션의
업로드와 보관 목록이 비어 있는 것은 기존 결과가 삭제되었다는 뜻이 아닙니다.
이전 원본과 증빙은 필요한 경우 별도로 안전하게 보관·이동합니다.

기본 시작 도구 회귀(모델/GPT/브라우저 실행 없음):

  .\.venv\Scripts\python.exe -B -m unittest tests.test_start_local -v

전체 평가 요구사항은 R&D_COMPLIANCE.md, API 계약은
docs/external-integration-api.md와 docs/data-contracts.md를 확인합니다.
